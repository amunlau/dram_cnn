## 0. 必须先记住的三条

1. **量化范围**：全部卷积层与两层全连接的**权重**和**层输入激活**，均为逐层对称 **signed INT8**（`zero_point=0`，整数域 `[-128, 127]`）。不是 uint8，不是逐通道量化。
2. **模型输出**：packed 与 ONNX 都只给出 2 维 **logits** `[z0, z1]`。图内**没有 Softmax**，末层 `head.3` 也**没有 ReLU**。
3. **部署后处理（图外，必做）**：对 logits 做 Softmax，取正类（下标 1）概率 \(p_1\)，与阈值 **τ = 0.52** 比较得到 0/1。不要把 logits 直接和 0.52 比较。

完整推理链：

```text
已预处理热图 X  [N, 31, 128, 32]
        │
        ▼
   网络前向（路径 A：INT8；路径 B：ONNX 浮点）
        │
        ▼
   logits = [z0, z1]          ← 模型到此结束
        │
        ▼
   p1 = softmax(z)[1]         ← 部署侧实现（浮点）
        │
        ▼
   ŷ = 1 if p1 ≥ 0.52 else 0  ← 部署侧实现
```

## 2. 量化方法

### 2.1 方案与硬约束

| 项 | 当前交付 | 明确禁止 |
|----|----------|----------|
| 方法 | 训练后量化（PTQ）。校准与 AdaRound **已经做完**，结果写进 packed | 部署侧不要再训练、不要再校准、不要做 QAT |
| 位宽 | **W8A8**：权重 8 bit + 激活 8 bit | 不要混用 INT16 / UINT8 权重 |
| 符号 | **signed INT8** | **不是 uint8** |
| 整数域 | `qmin = -128`，`qmax = 127` | 不要用 `[0, 255]` |
| 零点 | 权重、激活全部 **`zero_point = 0`**（对称） | 不要做非对称量化；量化后**不必减零点** |
| 粒度 | **逐层（per-tensor）一个 scale** | **禁止逐通道**（`weight_scale` 长度恒为 1，不是 `C_out`） |
| 覆盖 | stem、全部 stages 卷积、`head.0`、`head.3` 全部 INT8 | 不要把 stem / `head.3` 留成 FP32（旧交付的「保护首尾层」已取消） |
| 偏置 | `force_zero_bias=true`：BN 融合后丢弃折合偏置 | 不要按「完整 BN fold 必有 bias」加回来 |

核对：`manifest.json` 的 `quant_scheme`；`model/bias_audit.json` 中 `ok_no_bias=true`，`all_layers_int8=true`，`keep_fp32_layers=[]`。

### 2.2 量化映射（权重与激活同一套）

对浮点值 \(x\)、该张量标量 scale \(s>0\)：

```text
q     = clip(round(x / s), -128, 127)     # signed int8
x_hat = q * s
```

- \(\mathrm{round}\) 与 PyTorch `torch.round` 对齐（银行家舍入：恰为 `.5` 时靠偶数）。其他「四舍五入」与参考推理可能有逐元素差异；联调以 packed 参考推理为准。
- 因为 `zp=0`，整数乘加前 **不要** 再执行 `q - zp`。

**权重 scale**（打包时已算好，部署只读，禁止重算）：

```text
s_w = max(|W|) / 127
```

每层整张权重共用这一个 \(s_w\)。JSON 中写作 `weight_scale: [s_w]`（长度为 1 的数组）。

**激活 scale**（校准得到，部署只读，禁止重算）：

- 观测对象：该层 **输入激活**（不是输出）
- 离线校准（已完成）：验证集均匀抽 1024 条（seed=42），取 \(|x|\) 的 **99.9% 分位** 为 `amax`，再 `s_x = amax / 127`
- AdaRound 调整权重舍入后，激活 scale **又校准了一次**；交付 JSON 是**最终**值
- 网络输入进入 stem 的 \(s_x\) 等于 `input_quant_params.json` 的 `scale`（`0.0642202557541254`）

### 2.3 量化发生在流水线哪一步（部署不必重做）

```text
FP32 训练（Conv 无 bias；训练时有 BN、Dropout）
  → Conv+BN 融合：W' = W * (γ / sqrt(σ²+ε))
  → 丢弃融合偏置 b' = β + (b-μ)*(γ/sqrt(σ²+ε))   ← 硬件无偏置；不等于完整 BN fold
  → 非结构化 L1 剪枝，目标稀疏度约 30%（形状不变）
  → 短微调 5 轮
  → PTQ：定 scale → AdaRound → 再校准激活 → 打包 INT8
```

AdaRound 的结果已经写进 `qweight`。部署只加载 int8 权重和 scale，不要再学舍入。

部署拓扑：

```text
输入 [N,31,128,32]
  stem:     Conv3×3 + ReLU          → [N,64,128,32]
  stage0:   Conv+ReLU ×2 → MaxPool  → [N,64,64,16]
  stage1:   Conv+ReLU ×3 → MaxPool  → [N,128,32,8]
  stage2:   Conv+ReLU ×3 → MaxPool  → [N,256,16,4]
  stage3:   Conv+ReLU ×2 → MaxPool  → [N,256,8,2]
  pool:     GAP → Flatten           → [N,256]
  head.0:   Linear 256→256 + ReLU   → [N,256]
  head.3:   Linear 256→2            → [N,2]  logits
```

卷积一律 **3×3、padding=1、stride=1、dilation=1、groups=1、无 bias**。  
最大池化一律 **2×2、stride=2、无 padding**。  
无独立 BN，无 Dropout，无 Softmax，无任何 bias。  
全连接无偏置，计算为 \(y = x\,W^{\top}\)（`W` 形状 `[C_out, C_in]`）。

### 2.4 哪些量化、哪些不量化

| 量化（路径 A） | 不量化 |
|----------------|--------|
| 13 个有权重组件的权重 | MaxPool、GlobalAveragePool、Flatten |
| 每一层 MAC 的**输入激活**（含热图进 stem） | Dropout（推理关闭） |
| | ReLU：参考实现作用在反量化后的浮点上。`zp=0` 且 \(s>0\) 时，等价于对整数 \(\max(q,0)\) 再乘 scale |
| | **`head.3` 的输出 logits**（不做输出激活量化） |
| | **Softmax、与 0.52 的比较** |

「整网 INT8」的准确含义：所有 Conv / Linear 都是 INT8 乘加。  
**不是**「从输入到概率全程 INT8」。Softmax 始终在浮点后处理中完成。

### 2.5 整数乘加与层间再量化（路径 A）

对某一层，输入浮点为 \(x\)（原始热图或上一层 ReLU 后的浮点），`act_in_scale = s_x`，`weight_scale = s_w`（标量），int8 权重为 \(w_q\)。

**软件参考语义**（与 `infer_int8.py` 一致）：

```text
x_q = clip(round(x / s_x), -128, 127)          # signed int8
acc = Conv2d(x_q, w_q)  或  Linear(x_q, w_q)   # 无 bias；累加器用 int32
y   = acc * (s_x * s_w)                        # 反量化为 float
```

- 卷积层以及 `head.0`：`y = ReLU(y)`
- `head.3`：`logits = y`，形状 `[N, 2]`，**到此网络结束**

**硬件整数通路**（与仓库 `reports/GridCNN_W8A8_硬件整数推理参数提取.json` 一致）：

```text
acc_i32 = Σ (x_q * w_q)                        # 无 bias
y       ≈ acc_i32 * (s_x * s_w)
y       = ReLU(y)                              # 除 head.3 外
进入下一层前：
x_next_q = clip(round(y / s_next), -128, 127)  # s_next = 下一层 act_in_scale
```

要点：

- 乘加本身是 int8×int8 → int32 累加；scale 乘在累加之后。
- 下一层的 `act_in_scale` 只用于把**本层浮点输出**再量化成下一层的 `x_q`。
- `head.3` 之后没有下一层 MAC，**不要**把两个 logits 再量化成 INT8。
- 池化在参考实现中作用在反量化（及 ReLU）之后的浮点特征图上。若硬件在整数域做 MaxPool：对 `zp=0` 的对称量化，MaxPool 与「先反量化再池化再量化」在单调性上通常可对齐，但联调仍以参考推理为准。
- GAP（全局平均）含除法，建议在反量化后的浮点上做，再按 `head.0` 的 `act_in_scale` 量化 256 维向量。

## 4. 输出层没有 Softmax：含义、原因、部署必须做什么

### 4.1 模型实际输出

`head.3` 是无偏置全连接 `256 → 2`，**无激活函数**。输出：

```text
logits = [z0, z1]
```

- `z0`：负类（不故障）得分  
- `z1`：正类（故障）得分  

这两维**不是**概率：不必落在 `[0,1]`，之和也不为 1。  
中间层激活是 **ReLU**（stem、各卷积、`head.0`）。「输出层没有激活」不等于「全网没有激活函数」。

### 4.2 部署侧必须实现的后处理

对每个样本使用稳定 Softmax（先减行最大值）：

\[
p_1 = \mathrm{softmax}(z)_1 = \frac{e^{z_1}}{e^{z_0}+e^{z_1}}
\]

判决：

```text
ŷ = 1  若 p1 ≥ 0.52
ŷ = 0  否则
```

阈值只读 `model/deploy_threshold.json` 的 `threshold`（当前 **0.52**）。改 τ 不必改权重、不必重量化。

```python
import numpy as np

TAU = 0.52  # 与 model/deploy_threshold.json 保持一致

def predict_from_logits(logits: np.ndarray):
    """logits: [N, 2] -> (p_pos [N], pred [N] int64)"""
    z = logits - logits.max(axis=1, keepdims=True)
    exp = np.exp(z)
    prob = exp / exp.sum(axis=1, keepdims=True)
    p_pos = prob[:, 1]
    pred = (p_pos >= TAU).astype(np.int64)
    return p_pos, pred
```

PyTorch：`p_pos = torch.softmax(logits, dim=1)[:, 1]`。

ONNX Runtime 示例（路径 B，输入必须是 float32 热图）：

```python
import numpy as np
import onnxruntime as ort

sess = ort.InferenceSession(
    "onnx/grid_cnn_w8a8_pruned_allint8.onnx",
    providers=["CPUExecutionProvider"],
)
x = np.load("data/X_test.npy").astype(np.float32)
logits = sess.run(["logits"], {"input": x})[0]
p_pos, pred = predict_from_logits(logits)
```

### 4.3 为什么交付模型不加 Softmax

以下同时成立，Softmax 留在图外是交付约定，不是漏算子。

**（1）量化对象是 INT8 乘加，不是 Softmax**

要上的是对称 INT8 卷积/全连接。Softmax 需要指数和归一化除法，没有 \(x_q \cdot w_q\) 语义，也没有 `layer_quant_specs` 条目。把 Softmax 做成 INT8 层会使概率失真，无法对齐 τ=0.52 的验收数字。

**（2）训练与 PTQ 的输出空间是 logits**

训练使用交叉熵，损失内部做 `log_softmax`。网络约定输出未归一化得分。PTQ 不改拓扑、不改损失，只量化已有 Conv/Linear。图末再接 Softmax 会与训练定义和 packed 权重不一致。

**（3）激活量化只服务「下一层 MAC」**

W8A8 的激活量化发生在进入某一层之前。`head.3` 后面没有下一层卷积/全连接，两个 logits 只给判决使用。对概率再量化既无消费方，也会破坏与 0.52 的浮点比较。

正确切分：

```text
INT8 网络计算到 head.3 → 2 个浮点 logits
    → CPU / MCU 浮点 Softmax（或 §4.4 等价比较）
    → 与 0.52 比较
```

**（4）阈值是业务后处理，与权重解耦**

验收定义是「正类概率 ≥ 0.52」。Softmax 与 τ 都不写入 INT8 权重包。改阈值、打概率日志、或只输出 0/1，都不必重导模型。

软件侧若自行导出「带 Softmax 的 ONNX」，只是把后处理搬进图，**不能替代**本交付的 packed INT8，也**不能**当作当前 ONNX 的等价物。当前交付 ONNX 输出名为 `logits`，图内算子为 Conv / Relu / MaxPool / GlobalAveragePool / Flatten / MatMul，**不含 Softmax**。

### 4.4 板上只要 0/1 时可以不做 Softmax

下面两个判决完全等价（τ=0.52）：

\[
p_1 \ge 0.52
\quad\Longleftrightarrow\quad
z_1 - z_0 \ge \ln\frac{0.52}{0.48} \approx 0.080043
\]

需要把概率写入日志或给上游时，仍应算 Softmax。  
**禁止**把 `z1` 或 `z1-z0` 直接和 **0.52** 比较。

### 4.5 后处理禁止事项

| 错误做法 | 后果 |
|----------|------|
| 把 `z1`、`max(z0,z1)` 或 `z1-z0` 与 0.52 比较 | 量纲错误 |
| 对 2 维 logits 做 Sigmoid（单输出那套） | 本模型不是 1 维 logit |
| `argmax` 且不用阈值 | 等价于 τ=0.5，不是 0.52 |
| 使用训练阈值 0.76 | 与当前 INT8 模型不匹配 |
| 在 INT8 核里量化 Softmax | 概率失真 |
| 假设输出已是概率或已是 0/1 | 漏做后处理 |
| 用测试集重搜阈值作为上线 τ | 违反验收口径 |
| 给路径 B（ONNX）喂 int8 输入 | 图期望 float32 热图 |
| 给路径 A 跳过输入量化 | stem 激活 scale 对不上 |

正式验收：**测试集 + 固定 τ=0.52**。验证集仅用于联调。未经变更流程，不得用验证集重搜结果替换上线阈值。

- [ ] packed `format == gridcnn_w8a8_packed_v3`
