# 训练原理与验证集阈值搜索

本文面向「熟悉经典机器学习 / 梯度下降，但不熟悉本仓库选模与验收口径」的读者。  
操作命令见 [`user_guide.md`](user_guide.md)；配置字段见 [`project_configuration_reference.md`](project_configuration_reference.md) §7；排错见 [`troubleshooting.md`](troubleshooting.md)。

**一句话**：网络用交叉熵学习「这条样本有多像故障」的**分数**；真正报不报故障，还要在验证集上再选一把**决策刀** \(\tau\)。选哪一轮权重，看的是「这把刀切完之后的 F1」，不是训练损失降到了多少。

文中会专门回答两个常见疑问：验证集搜阈是不是业内通用做法（§4.2）；用搜阈后的 F1 做早停为何合理、却不是最主流、以及为何高峰容易很早（§7）。

---

## 1. 先对照你熟悉的方法

| 你熟悉的 | 本项目实际做的 |
|----------|----------------|
| 用损失（MSE / 交叉熵）衡量拟合，梯度下降更新参数 | **相同**：训练集上加权交叉熵 + Adam 更新 GridCNN |
| 损失降到平台 ≈ 模型训好了 | **不够**：损失还可以再降，验证集 F1 可能已经变差（过拟合） |
| 逻辑回归 / Softmax 后默认 \(p\ge 0.5\) 判正类 | **0.5 只作对照**；部署用验证集搜到的 \(\tau\) |
| 模型直接等于分类器 | **模型 = 打分器**；分类器 = 打分器 + 阈值 \(\tau\) |
| 交叉验证选超参 / 早停看验证误差 | **同类思想**：用验证集指标选 \(\theta\)，但指标是「搜完 \(\tau\) 之后的 F1」 |

可以把流程看成**两层优化**，内层你已经会，外层是本仓库多出来的部分：

```text
内层（可微，每个 batch）：θ ← Adam(∇ 加权交叉熵)
外层（不可微，每个 epoch 结束）：在验证集上扫 τ，用 F1(θ, τ) 决定是否保存这套 θ
```

F1 来自硬判决 \(\hat y = 1[p \ge \tau]\)，对 \(\tau\) 不可微，**不能**当成训练损失反传。所以必须把「学分数」和「定刀」拆开：内层只学 \(\theta\)，外层再选 \(\tau\)。本仓库默认还把外层得到的 F1 拿来**选哪一轮 \(\theta\)**（早停），等于把「选模」和「选刀」绑在同一标量上；这与验收口径一致，但和「先用 AUC 选模、训练后再搜一次 \(\tau\)」的主流写法不同，详见 §7。

## 2. 任务与模型输出是什么

任务是二分类：锚点时刻 \(t\) 之前的 CE 热图 \(X\in\mathbb{R}^{31\times 128\times 32}\)，预测未来 `label_horizon_seconds`（默认 300 秒）内是否出现工单级故障。标签 \(y\in\{0,1\}\)。

GridCNN 最后一层输出 **2 维 logits** \((z_0, z_1)\)。正类概率为：

\[
p = \mathrm{Softmax}(z)_1 = \frac{e^{z_1}}{e^{z_0}+e^{z_1}} \in (0,1)
\]

实现：`src/dram2cnn/engine/trainer.py` 的 `_collect_eval`、`src/dram2cnn/engine/predictor.py` 推理路径，都取 `softmax(logits)[:, 1]`。

到这一步，**还没有「报故障 / 不报」**。\(p\) 只是排序用的分数。判决是：

\[
\hat y = \mathbf{1}[p \ge \tau]
\]

\(\tau\) 不由梯度下降给出，而由下一节的网格搜索给出。

## 3. 内层：训练集上如何更新权重

每个 epoch 对训练集反复做：前向 → 损失 → 反向 → `optim.step()`。损失是 **带类别权重的交叉熵**（`focal_gamma` 默认 0，即普通加权 CE；GridCNN-Deep 不要开 Focal，易 NaN）。

### 3.1 为何要加权 / 过采样

正类远少于负类。若对每个样本一视同仁，梯度会被多数负类主导，模型容易「几乎总预测负类」。此时固定 \(\tau=0.5\) 的 F1 会很差——这往往是**损失目标与 F1 目标不一致**，不等于「没有调阈值的空间」。

本项目默认两件互补的事（`configs/train.yaml` → `imbalance`）：

1. **类别权重**（改错分代价）  
   在空窗剔除、切分之后的 `y_train` 上统计 \(P\)、\(N\)（**过采样之前**）。默认 `weight_scheme: sqrt`：

   \[
   w_{-}=1,\quad w_{+}=\min\bigl(\sqrt{N/P},\; \texttt{positive\_weight\_cap}\bigr)
   \]

   cap 默认 30。`inverse_freq` 则用 \(N/P\) 本身，更激进。

2. **正样本索引过采样**（改每个 epoch 见到多少正例）  
   `positive_oversample_factor` 全量默认 2：每个正样本索引在训练序列里出现两次。权重**不**按过采样后的频次重算，避免双重放大。

DDP 下不用 `WeightedRandomSampler`（与 `DistributedSampler` 叠加语义复杂）。实现见 `src/dram2cnn/engine/imbalance.py`、`src/dram2cnn/models/losses.py`。

### 3.2 优化器与早停预算

- Adam，`lr=0.001`，`weight_decay=1e-4`，梯度裁剪 `max_grad_norm=1.0`。  
- `epochs=300` 是上限；真正何时停看验证指标 + `patience`（全量 **50**，冒烟 YAML 才覆盖为 6）。  
- checkpoint 路径如 `runs/<run_name>/<会话>/checkpoints/grid_cnn.pt`。

内层结束时你得到的是一套 \(\theta\)，以及每条验证样本上的 \(p_i\)。外层从这里开始。

## 4. 外层：验证集搜阈是什么、怎么做

### 4.1 含义

**搜阈** = 网络权重**冻结**，只在验证集的已有概率 \(\{p_i\}\) 上，试一串候选 \(\tau\)，按预定目标（主实验是 **F1 最大**）挑一个。

这一步：

- **不**反向传播、**不**改卷积权重；  
- **只**改「概率到 0/1」的切点；  
- 必须在**验证集**上做。测试集标签在定 \(\tau\) 时不可见，否则验收虚高。

直观对应：逻辑回归学到 \(p=\sigma(w^\top x)\) 之后，仍要选 cutoff；SVM 的间隔分数也要再定报警线。教材里常省略这一步，是因为默认了 0.5 且默认分数已校准。

### 4.2 这是不是业内通用做法？

**验证集上选决策阈值、测试集锁死再用，属于二分类（尤其是类别不平衡）的通用做法。** 教材和入门示例经常省略它（默认 \(p\ge 0.5\)）；工程、论文、风控/告警/医疗筛查里反而更常单独做这一步。

业内通常的路径是：

1. 在**验证集 / 校准集**上画出 ROC 或 PR 曲线；  
2. 按业务目标选一个工作点（operating point）：最大 F1、给定精确率下最大召回、Youden’s J、期望代价最小等；  
3. 把这个 \(\tau\) **冻住**，拿到测试集或线上只用这一把刀。

这和本仓库「验证集搜阈、测试集不许再搜」是同一条规矩。sklearn 的 `precision_recall_curve`、各种 F1-optimal threshold 教程、生产里的 cutoff 调参，都是这件事。**禁止用测试集调阈值**，也是防泄漏的常规要求。

网格扫 \(\tau\)（本仓库默认 0.10～0.90、步长 0.02）是其中最朴素、也完全正当的实现：候选不多、可复现、不依赖梯度。更细的做法是沿 PR 曲线上所有跳变点搜（评估里 `oracle_on_test` 用 step=0.01，本质一样，但那一步只作分析、不当验收）。

哪些是通用、哪些是本项目的选择：

| 做法 | 是否通用 |
|------|----------|
| 模型学分数，判决用单独的 \(\tau\) | **通用** |
| \(\tau\) 只在验证集上定，测试集固定评价 | **通用、应遵守** |
| 不平衡或分数未校准时不用默认 0.5 | **通用建议** |
| 用「F1 最大」当选刀目标 | **常见**，但不是唯一；有明确代价矩阵或运维约束时，会改用代价最小、召回下限等。本仓库工程实验的 `recall_first` / `min_recall` 更接近后一类 |
| 类别权重 + 过采样 | **常见**，和搜阈互补：前者改训练，后者改部署工作点 |
| **每个 epoch 都搜一遍 \(\tau\)，并用 `best_f1` 做早停** | **合理，但不是最主流的早停指标**。更常见的是早停盯 val loss / AUC / PR-AUC，**训练结束后再搜一次 \(\tau\)**。把「选模」和「选刀」绑在同一标量上，与主验收 F1 一致，但该量对分数分布更敏感，高峰容易出现得很早（详见 §7） |

不要和另外两条常见路混为一谈：

- **概率校准**（Platt、isotonic）：让 \(p=0.7\) 真表示约 70% 正例，之后 0.5 才更有意义。本仓库**没有**做校准，而是直接搜 F1 最优刀——在「只关心分类对错、不关心概率数值含义」时完全常见。  
- **改损失函数直接优化 F1**：F1 不可微，一般不用来反传；交叉熵（或 focal）训练 + 事后选 \(\tau\)，才是主流组合。

结论：**搜阈本身是通用做法**；本仓库特别的是主实验用 F1 最大当刀的目标，并且用这个 F1 **每个 epoch 选 checkpoint**。

### 4.3 为何 0.5 常常不是最好的刀

交叉熵鼓励「正类 \(p\) 尽量大、负类尽量小」，**不保证**分数以 0.5 为分界、也不保证校准（\(p=0.7\) 不一定真有 70% 故障率）。加权与过采样还会把分数整体抬高或压低。

因此会出现：

- 多数正类落在 0.6～0.9、负类落在 0.2～0.6 → \(\tau=0.5\) 召回很高、精确率很差；  
- 或分数整体偏低 → \(\tau=0.5\) 几乎报不出正类。

同一套 \(\{p_i\}\)，只改 \(\tau\)，F1 可以差出一大截。这不是实现错误，是**工作点**问题。

### 4.4 网格怎么扫（主实验默认）

配置在 `configs/train.yaml` 的 `threshold_search`（实现 `src/dram2cnn/engine/metrics.py` → `search_threshold`）：

| 项 | 默认 | 含义 |
|----|------|------|
| `enabled` | true | 训练结束把最优 \(\tau\) 写入 `best_threshold.json` |
| `objective` | `f1` | 主实验：最大化 F1 |
| `min` / `max` / `step` | 0.1 / 0.9 / 0.02 | 候选 \(\tau \in \{0.10, 0.12, \ldots, 0.90\}\)（约 **41** 个点） |

对每个候选 \(\tau\)：

1. \(\hat y_i = 1[p_i \ge \tau]\)（注意是 **≥**，与 argmax 在恰好 0.5 时可能差一条样本）；  
2. 对照验证集 \(y_i\) 算精确率 \(P\)、召回率 \(R\)、F1 \(= 2PR/(P+R)\)（某一侧为 0 则记 0，`zero_division=0`）。

`objective: f1` 的取胜规则是元组比较：

```text
先比 F1 大；并列再比召回率大；再并列取更小的 τ
```

对应代码：`max(..., key=lambda r: (r["f1"], r["recall"], -r["threshold"]))`。

### 4.5 示意数字（不是某次实验的实测）

假设验证集 100 条，其中 30 个真故障，模型已经给出 100 个 \(p_i\)：

| \(\tau\) | 报出的正类 | 其中真故障 | 精确率 | 召回率 | F1 |
|----------|------------|------------|--------|--------|-----|
| 0.50 | 60 | 28 | 0.47 | 0.93 | 0.62 |
| 0.76 | 23 | 20 | 0.87 | 0.67 | **0.76** |
| 0.90 | 8 | 8 | 1.00 | 0.27 | 0.42 |

同一套概率，刀从 0.50 改到 0.76，F1 从 0.62 升到 0.76。  
交付实验第 2 轮就接近这种形态：分数整体偏高，必须把 \(\tau\) 抬高，搜阈 F1 才最高。

### 4.6 每个 epoch 里搜几次、存的是哪一次

每个 epoch 验证阶段都会搜一遍，得到**这一轮**的 `best_t` 与 `best_f1`。  
若本轮 `best_f1` 创新高，则：

- 覆盖保存 `checkpoints/grid_cnn.pt`（这套 \(\theta\)）；  
- 写入 `best_val_metrics.json`（含该轮的 \(\tau\) 与两套指标）；  
- 覆盖 `val_predictions.csv`（该轮验证集 \(y, p\)；其中诊断列 `y_pred` 是 **argmax**，与搜阈判决不是同一列）。

训练循环结束后，再用**最后一次成功保存**的 `val_predictions.csv`（即历史最优轮的概率）再搜一次，写入 `best_threshold.json`。推理默认读这个文件。

因此磁盘上的权重和阈值，都对应「验证搜阈 F1 最高的那一轮」，**不是**最后一轮、也不是训练损失最小的一轮。这里已经把「选哪套 \(\theta\)」和「选哪把 \(\tau\)」绑在同一个 `best_f1` 上；与主流「先用 AUC 选模、结束后再搜阈」的对比见 §7。

### 4.7 工程实验的其它 `objective`（主验收不用）

主评价指标实验（`exp_full_f1_*`）保持 `objective: f1`。召回/精度工程实验会换目标，网格仍在验证集上扫：

| `objective` | 选取规则 |
|-------------|----------|
| `f1` | 最大化 F1（默认） |
| `f_beta` | 最大化 \(F_\beta\)（\(\beta>1\) 更偏召回） |
| `recall_first` | 在精确率 ≥ `min_precision` 下最大化召回 |
| `min_recall` | 在召回、精确率下限内最大化精确率；不满足则逐步放宽（宁报勿漏） |

模板见 `configs/threshold_profiles.yaml`。这些**不替代**主实验的 F1 验收。

## 5. 一整轮训练在干什么（时序）

```text
for epoch = 1 .. 300:
  模型.train()
  for batch in 训练集:
      logits = CNN(X)
      loss = 加权交叉熵(logits, y)
      反向传播；梯度裁剪；Adam 更新 θ

  同步各卡后，rank0：
      模型.eval()，验证集算全部 p_i
      ① 固定 τ=0.5 → f1@0.5、精确率、召回率…
      ② 网格搜 τ → best_t、best_f1
      ③ ROC-AUC、PR-AUC（只看分数排序，不依赖某一把刀）
      若 early_stop_metric（默认 best_f1）创新高 → 保存权重
      否则 patience 计数 +1；满 50 则全体 rank 一起停

结束后 rank0：用最优轮的 val_predictions.csv 再搜 τ → best_threshold.json
```

步骤 ② 的 `best_f1` 默认就是早停所用的标量；步骤 ③ 的 AUC / PR-AUC 每轮都算，但默认**不**拿来覆盖 checkpoint。为何如此、以及和主流早停的差别，见 §7。

对应实现：`src/dram2cnn/engine/trainer.py`（训练 step 约在损失反传处；验证与搜阈在 `_collect_eval` 之后）。

多卡时只有 rank0 做验证与写盘，再用广播让各进程同时 break，避免有的卡还在训、有的卡已经停。

## 6. 日志里三列不要混读

每个 epoch 都会打印大致如下（数字随实验变）：

```text
Epoch k | loss=... | roc_auc=... | pr_ap=... | f1@0.5=... | best_f1=... | best_t=...
```

| 字段 | 在哪算 | 用哪把刀 | 用途 |
|------|--------|----------|------|
| `loss` | 训练集 | 无（软概率） | 看拟合是否还在进行；**不能**用来选部署权重 |
| `f1@0.5` | 验证集 | 固定 0.5 | 对照；分数整体偏移时会和 `best_f1` 差很多 |
| `best_f1` / `best_t` | 验证集 | 本轮网格搜到的 \(\tau\) | **默认早停与选 checkpoint** |
| `roc_auc` / `pr_ap` | 验证集 | 无（排序） | 看「正类是否倾向于比负类分数高」；与具体 \(\tau\) 无关 |

`early_stop_metric` 默认 `best_f1`，即用上表第三行那个标量跟历史最优比。可选 `avg_precision`、`roc_auc`、`f1_at_0p5` 等，见配置手册 §7.2 / §13。

常见误读：后期 `loss` 更低、`f1@0.5` 更高，就认为应改用最后一轮。本仓库**明确不这样选**。交付实验里训练损失从约 0.37 降到 0.08，固定 0.5 的 F1 后期可到 0.72+，但搜阈 F1 与 AUC 在第 2～3 轮见顶后回落——主分界面已经学到，再训是过拟合。完整数字见 [`../delivery/nobias-symint8-20260818/evidence/notes/训练早停与第2轮最优说明.md`](../delivery/nobias-symint8-20260818/evidence/notes/训练早停与第2轮最优说明.md)。三列为什么会分道、以及为何早停用 `best_f1` 会显得「第 2 轮就最好」，见下一节。

## 7. 选模和选刀：为何用 `best_f1` 早停合理、却不是最主流

上一节的三列其实在回答**两个不同的问题**。把它们绑在同一个早停标量上，是本仓库相对「教科书流程」最需要解释的一点。

### 7.1 两件不同的事

| | 选模：这套权重 \(\theta\) 好不好？ | 选刀：用哪个 \(\tau\) 做 0/1 判决？ |
|--|--|--|
| 问的是 | 正负类有没有被**排开**（排序质量） | 在已有分数上，哪条分界线的 F1 / 代价最好 |
| 理想指标 | val loss、ROC-AUC、PR-AUC | 在验证集上搜 \(\tau\) |
| 对分数的要求 | 只关心相对顺序：正类 \(p\) 是否整体高于负类 | 还关心**绝对位置**：分数堆在 0.3 还是 0.8 |

**排序好**和 **F1 高**不是一回事。  
ROC-AUC = 随机抽一对（正、负），正类分数更高的概率，**跟你把刀架在 0.5 还是 0.76 无关**。  
F1 必须先切成 0/1，所以**同一套排序，换一把刀，F1 可以差一截**。

### 7.2 主流写法 vs 本仓库

更常见的工业 / 论文流程把两步拆开：

```text
训练中：用「与刀无关」的量早停（val loss / AUC / PR-AUC）→ 得到最好的 θ*
训练完：只对 θ* 在验证集上搜一次 τ* → 部署
```

本仓库默认是：

```text
每个 epoch：对当前 θ 搜一遍 τ，得到 F1(θ, τ*(θ))，即日志里的 best_f1
用这个 F1 决定要不要覆盖 checkpoint  ← 选模和选刀绑在同一个数上
```

这不是错误，而是**用验收指标直接当选模指标**。赛题 / 项目主评价看「验证集定阈后的 F1」，这样做口径一致；代价是这个数比 AUC 更「闹」，高峰可以来得很早。

可在 `configs/train.yaml` 把 `early_stop_metric` 改成 `avg_precision` 或 `roc_auc`，就回到更主流的「先选排序器、再选刀」。主实验保持 `best_f1`，是为了和 F1 验收对齐。

### 7.3 主流为什么爱盯 val loss / AUC / PR-AUC

这些量有共同特点：**不依赖某一把刀**。

- **val loss（交叉熵）**：每个样本的软概率都贡献，变化平滑。过拟合时验证损失往往先升，信号比较稳。缺点：和 F1 不对齐（损失低不等于 F1 高）。本仓库日志打印的是**训练**损失，不是验证损失，更不能拿来选部署权重。  
- **ROC-AUC**：只看排序。权重微调一点，只要相对顺序不大变，AUC 几乎不动。  
- **PR-AUC（average precision，日志里的 `pr_ap`）**：也是排序，但更盯「把正类排在前面」，不平衡时比 ROC-AUC 更贴「找故障」。

典型流程是：用其中一个做早停，**最后**再在验证集上选 operating point。  
「先有一个排得好的打分器，再按业务选工作点」——刀可以以后按精确率 / 召回率改，不必重训。

把 F1 写进早停，等于宣布：**关心的就是「现在这套分数 + 现在这把最优刀」的分类成绩**，而不是「以后还可以再调刀的排序器」。

### 7.4 为什么 `best_f1` 对分数分布更敏感

记 \(\mathrm{F1}(\theta)=\max_\tau \mathrm{F1}(\theta,\tau)\)。它比 AUC 多了两层抖动。

**第一层：硬判决。**  
F1 来自 TP / FP / FN 的整数计数。验证集上有人分数刚过刀或刚没过，\(p\) 动 0.01，计数就跳 1，F1 跟着跳。AUC 只问「谁排在谁前面」，很多小扰动它几乎不动。

**第二层：刀本身在动。**  
每个 epoch 的 \(\tau^*\) 可以变。交付那次：第 2 轮 \(\tau=0.76\)，第 3 轮 0.74，第 25 轮 0.86，后期甚至 0.30。  
于是比较的不是「同一把刀下谁更好」，而是：

```text
第 2 轮：θ₂ 配 0.76 的 F1    对    第 25 轮：θ₂₅ 配 0.86 的 F1
```

分数整体平移（校准变了、被类别权重推高）时：

- AUC：正负相对顺序若还在，可以几乎不变；  
- `f1@0.5`：刀钉死在 0.5，分数一漂，这列会大变；  
- `best_f1`：会**换一把刀去追**那坨分数，尽量把 F1 补回来。

所以 `best_f1` 有时看起来「很能扛」，有时又会在某一轮突然顶一下——因为那一轮分数堆的位置，刚好能切出一对特别好的精确率 / 召回率。  
**高峰可以来自「排序最好」，也可以来自「这一轮的分数形状特别好切」。** 后者对训练动态很敏感，所以容易早出现、也容易下一轮就没了。

用本次交付的实测表对照（来自同一次训练的 `epoch_metrics.csv`，不是 §4.5 的示意）：

| 轮次 | 训练损失 | f1@0.5 | 搜阈 F1（早停） | 搜到的 τ | ROC-AUC |
|------|----------|--------|-----------------|----------|---------|
| 1 | 0.444 | 0.600 | 0.744 | 0.90 | 0.885 |
| **2（保存）** | 0.370 | 0.626 | **0.760** | **0.76** | 0.890 |
| 3 | 0.367 | 0.648 | 0.757 | 0.74 | **0.893**（排序最好） |
| 25 | 0.156 | **0.725** | 0.728 | 0.86 | 0.865 |
| 52（最后） | **0.086** | 0.699 | 0.716 | 0.90 | 0.822 |

读法：

- 第 25 轮：0.5 那把刀更好用了（0.626→0.725），看起来「分类更像教科书」。  
- 但排序已经变差（AUC 0.890→0.865），换最优刀之后的 F1 也掉了（0.760→0.728）。  
- 若早停盯 `f1@0.5` 会错爱第 25 轮；盯 AUC 会更爱第 3 轮；盯 `best_f1` 会爱第 2 轮。  
  **三列在选不同的东西。**

第 2 轮分数整体偏高（固定 0.5 时召回约 0.91、精确率约 0.48），必须把刀抬到 0.76，F1 才到 0.760。这正是「分数分布形状」在起作用，不只是「分开了没有」。第 43、49 轮搜到 \(\tau=0.32 / 0.30\)，是排序变差后的病态工作点，进一步说明后期权重不宜部署。

### 7.5 为什么高峰容易很早

两件事叠在一起。

**（1）排序本身就很快到顶。**  
CE 热图模式粗、模型够大（约 3.18M 参数）、Adam `lr=0.001`、大 batch、正类权重大且过采样 ×2。主分界面一两轮就拟合完。AUC 第 3 轮就见顶（0.893），之后掉到第 52 轮的 0.822。这已经是过拟合，和用不用搜阈无关。

**（2）`best_f1` 还额外奖励「好切的分数形状」。**  
早期模型偏「欠拟合但分数成团」：正类概率普遍偏高，一把高阈值就能同时拿到还行的精确率和召回。  
再训下去：训练集交叉熵继续降，分数被推得更开、更极端，最优 \(\tau\) 乱漂，PR 曲线上那个最尖的工作点反而变钝。  
于是 **AUC 已经开始掉的同时，`best_f1` 掉得更明显、也更早**——它既吃排序变差，又吃「好切的形状」消失。

若早停盯 AUC，往往会停在第 3 轮附近（和本交付第 2 轮几乎同学期）；不会出现「损失还在降、0.5-F1 还在升、却在第 2 轮保存」这种看起来更刺眼的反差。  
刺眼，是因为 `f1@0.5` 和 `loss` 还在往「教材意义上的更好」走，而选模标量已经掉头了。

这不等于 patience 设错，也不等于只训了 2 轮：`patience=50`，训练跑到第 **52** 轮才停；磁盘权重是历史最优（第 2 轮）。三次全量最优都在第 2～6 轮，测试 F1 都在约 0.767。现象说明见 [`../delivery/nobias-symint8-20260818/evidence/notes/训练早停与第2轮最优说明.md`](../delivery/nobias-symint8-20260818/evidence/notes/训练早停与第2轮最优说明.md)。

### 7.6 为什么仍说「合理」

合理之处在于**验收就是验证集定阈后的测试 F1**。  
早停盯 `best_f1`，等于直接优化最终要报的那个流程，而不是优化一个「以后再调刀」的代理指标。  
本次测试部署 F1≈0.7679，还略高于验证 0.760，说明第 2 轮那个点不是验证集噪声尖峰。

若改成主流写法（早停 AUC 或 PR-AUC，最后再搜一次 \(\tau\)）：

- 可能会留下第 3 轮权重（AUC 最高 0.893）；  
- 该轮搜阈 F1 是 0.757，和 0.760 几乎一样；  
- **不会 magically 训到第 25 轮还更好**，因为那时排序已经坏了。

所以争议不在「该不该搜阈」（该搜，而且要在验证集上搜），而在 **每个 epoch 都把搜完的 F1 拿来当早停**，会让曲线更尖、最优轮更早。这是指标性质，不是没训够。

## 8. 测试集：部署口径 vs 事后最优

定 \(\tau\) 只用验证集。测试集上：

\[
\hat y_{\text{test}} = \mathbf{1}[p_{\text{test}} \ge \tau^{*}]
\]

\(\tau^{*}\) 来自训练目录 `best_threshold.json`（推理写入 `predictions.csv` 的 `threshold` 列）。  
**禁止**用测试标签再搜一把刀当作验收——那叫偷看答案。

评估脚本因此写两段（`src/dram2cnn/engine/evaluator.py`）：

| 段 | 含义 | 能否当验收 |
|----|------|------------|
| `deployment` / `metrics.json` 顶层 | infer 已经用验证集 \(\tau^{*}\) 切好的 `y_pred` | **能**（项目主指标） |
| `oracle_on_test` | 在测试集上再网格搜 F1 最优 \(\tau\)（评估时 step=0.01，仅分析） | **不能** |

量化、剪枝会改变 \(p\) 的分布，因此那些阶段会在**验证集上重新搜 \(\tau\)**，再拿到测试集上固定评价。原理相同，只是换了一套分数。当前 INT8 交付阈值为 0.56，就是剪枝微调后在验证集上重搜得到的，不是训练阶段的 0.76。

推理读阈值：`src/dram2cnn/engine/predictor.py` 的 `_resolve_threshold`。文件缺失才回退 0.5；**JSON 损坏会直接报错**，不会静默回退。

## 10. 和经典「等到收敛」差在哪（收束）

交叉熵不会自动停在 F1 最大的地方。它会尽量把训练集分得更开，分数分布会漂，每一轮最优 \(\tau\) 都可能变（交付实验第 2 轮 \(\tau=0.76\)，后期甚至出现 0.30 附近的病态工作点）。

因此本仓库的选模规则是：

1. 用梯度下降学 \(\theta\)（内层）；  
2. 每轮在验证集上为这套 \(\theta\) 搜 \(\tau\)，记下 F1（外层）；  
3. 只保留历史上 F1 最高的 \(\theta\)；  
4. 把对应的 \(\tau^{*}\) 冻结，拿到独立测试集上评价。

「学分数」和「定刀」必须拆开（F1 不可微）；「选哪一轮 \(\theta\)」本仓库默认仍用定刀之后的 F1，这是和验收对齐的选择，不是梯度下降本身的要求（§4.2、§7）。

记住一句即可：**训练用梯度下降学分数；验证集搜阈是在这堆分数上试约 41 把刀，用切得最好的那一把的 F1 决定保存哪一轮，再用同一把刀去切测试集。**
