## 0. 相对上一轮的关键修正

上一轮目录 `prune_compare_fp32_bn_filter_uL1_uL2_r010-080_ft10` 存在**本质错误**：非结构化剪枝在 `prune.remove` 之后立刻微调，零权重被 Adam 训回，落盘模型稀疏率≈0，但表中仍按目标稀疏率报告理论算力。

**本轮修正**：

1. 非结构化剪枝 `finalize=False`，微调期间保留 `weight_mask`（前向始终乘 mask）；
2. 微调结束后再 `finalize_unstructured_pruning`（`prune.remove`）固化；
3. 用固化后的稀疏率刷新 `stats`，再评估、存盘。

已对全部 16 个非结构化 checkpoint 实测：微调后稀疏率与目标 **逐档一致**（0.10…0.80）。结构化路径不变。

## 1. 结论摘要

1. **结构化（BN-γ / Filter L1）**：短时微调后测试 F1 相对 Base-new 多在约 ±0.01 内；约 **50%–60%** 通道剪除时可达接近或略优于基线的 F1，同时理论 GMACs 可降至约 **0.21–0.32**（基线约 1.21）。
2. **非结构化 L1 / L2**（本轮为**真实稀疏**模型）：八档测试指标仍完全一致（w^2 与 |w| 等价）；相对基线最差约 **ΔF1≈−0.016**（30% 稀疏），多数档位掉点小于 0.01。
3. 若需**无需稀疏算子**的实际加速，优先 **Filter L1 / BN-γ**；非结构化结果现已可代表「稀疏推理」精度上界，但仍依赖稀疏内核才能兑现延迟收益。

## 4. 分析与思考



### 4.1 结构化

- BN-γ 与 Filter 在相同名义比例下参数量/理论 GMACs 相同（同一套通道切片），精度曲线因保留通道集合不同而略有差异。  
- 高比例下仍接近基线，说明在本任务与 10 epoch 微调下通道冗余较大。  
- 全量训练未对 γ 做 L1，BN-γ 非完整 Network Slimming；Filter L1 不依赖该正则，二者可互补。



### 4.2 非结构化（修订后）

- 本轮精度对应**真实稀疏权重**；与上一轮「剪完再稠密微调」不可直接横向对比。  
- L1/L2 指标一致，再次确认标量幅度排序等价；单独归档便于审计，而非提供第二种有效压缩算法。  
- 理论 GMACs 现与存盘稀疏率一致；稠密 GPU 上延迟未必下降，需稀疏内核。



### 4.3 建议

1. 部署友好优先：Filter L1 或 BN-γ，比例可优先看 **0.50–0.70**。
2. 各模型使用**各自** val 搜阈，勿混用 Base-new 的 τ=0.78。
3. 旧目录 `…_ft10`（无 keepmask）中非结构化结果应视为无效压缩结论，以本目录为准。
